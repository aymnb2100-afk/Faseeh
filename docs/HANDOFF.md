## 1. الجاهزية: 67%

**100% تعني:** نقدّم المشروع ونحن واثقون تماماً أنه ما فيه شي يحرجنا يوم العرض: الواجهة، والسيرفرات، ودقة المودل على أصوات حقيقية.

| الجزء | الوزن | الحالة | ليش مو 100% |
|---|---|---|---|
| الواجهة (اللابتوب والجوال) | 20% | 95% | آخر التعديلات (الأخطاء الوهمية، زر التسجيل، التنبيه، نافذة الأخطاء، 100% قراءتك صحيحة) ما انجربت على جوال حقيقي بعد الرفع |
| توقيت كلمات القارئ | 10% | 95% | مفحوص آلياً على الصوت؛ باقي تأكيد الفريق لسورة النبأ (التظليل + استمع للكلمة) |
| السيرفرات (Hugging Face + جهاز الفريق + التبديل التلقائي) | 15% | 100% | مزامنة HF ✅ (Run #1)، جهاز الفريق `cuda` ✅، التحديث التلقائي مرفوع ✅ |
| **دقة المودل على أصوات حقيقية** | **40%** | **40%** | أرقام البنشمارك ممتازة، لكن **ولا تجربة حقيقية** على صوت الفريق للحين (كل التجارب السابقة كانت في وضع العرض التجريبي بالغلط). تسجيلات الفريق (`evaluate.py own`) ما انعملت. الحركات أضعف نقطة. |
| التقرير والعرض (المخططات، التقرير، خطة يوم العرض) | 15% | 50% (تقدير) | خارج ما اشتغلنا عليه هنا؛ يحتاج تأكيد من الفريق |

**المجموع ≈ 0.2×95 + 0.1×95 + 0.15×100 + 0.4×40 + 0.15×50 = 67%**

### الطريق إلى 100% (بالترتيب)
1. تجربة حقيقية على faseeh.space: الإخلاص صح، ثم بغلط متعمد، ثم تسجيل صامت (لابتوب + جوال). ← تكشف دقة المودل الفعلية.
2. تسجيلات الفريق + `evaluate.py own` ← رقم حقيقي للتقرير.
3. تأكيد سورة النبأ والجوال.
4. حسب النتائج: تحسين الحركات / الإنذارات الكاذبة (معايرة على 10 شيوخ).
5. مراجعة التقرير وخطة يوم العرض.

## 2. قواعد الشغل (لا تتغير إلا إذا قال الفريق)

### طريقة التواصل
- الرد **بالعامية السعودية البسيطة**، مختصر وواضح، بدون مصطلحات تقنية بلا داعي.
- لكل تعديل: **خطوات التشييك، اللابتوب منفصل عن الجوال** (يشيّكون اللابتوب أول).
- أي تعديل طُلب للابتوب وينطبق على الجوال: **طبّقه على الجوال كمان** بدون سؤال.
- الفريق يكره الزوائد ("بدون زوايد"): لا تضيف شي ما انطلب. اقترح، وانتظر الموافقة.
- **لا ألوان في مربع النسبة** (طلب صريح).
- قبل ما تقول "انرفع/صح": **شيّك بنفسك** على الريبو العام (`git clone`/`pull`) أو بالاختبار.

### الكود
- **الكلاسات في JS تطابق مخطط الكلاسات (UML) للمادة:** لا تضيف دوال جديدة على كلاسات النموذج. أي شي للواجهة يكون دوال مساعدة منفصلة.
- الواجهة ملف واحد `index.html` (JS بدون مكتبات)، 13 لغة عبر `TEXT.xx` (أي نص جديد يُترجم للـ13).
- كل تعديل: اختبار Playwright (لابتوب + آيفون 13 + آيفون SE) قبل التسليم.
- بعد كل تعديل يُبنى: `index.html` + `standalone/Faseeh.html` (`python3 tools/build_standalone.py`) + `Faseeh_repo.zip`.
- ملاحظة لـ Claude: في المحادثة الأصلية المصدر كان `faseeh.html` (جزء بدون head) ويُبنى منه `index.html`. في محادثة جديدة: **`index.html` في الريبو هو المصدر**، عدّل عليه مباشرة.

### الرفع للريبو (الفريق يرفع يدوياً عبر GitHub)
- **احذف الملف القديم من التنزيلات قبل تنزيل الجديد**، وإلا ينحفظ `index (1).html` والموقع ما يقرأه.
- `index.html` ← الصفحة الرئيسية للريبو.
- `reciters.json` ← داخل `data/` (تأكد فوق مكتوب `Faseeh / data`).
- ملفات السيرفر ← داخل `server/...` بنفس المسار. رفع مجلد كامل = اسحب المجلد نفسه.
- انتظر ✅ في Actions، ثم Ctrl+F5.

## 3. كيف يشتغل المشروع

```
المستخدم ── faseeh.space (GitHub Pages، من فرع main)
               │  يختار السيرفر بنفسه كل دقيقة:
               ├─► جهاز الفريق (RTX 2080، سريع)   https://barcode-stash-footsore.ngrok-free.dev
               └─► Hugging Face (CPU، دائم)          https://lowkeyo-faseeh-server.hf.space
GitHub (main) هو المصدر الوحيد:
   server/hf_space/**  ──(Action: sync-hf-space.yml)──► Hugging Face Space
   server/hf_space + server/local ──(كل دقيقتين)──► جهاز الفريق (Docker)
```

- **المودل:** Quran Muaalem (`obadx/muaalem-model-v3_2`)، بدون تدريب (قرار الفريق). الإعدادات: `config.json` (votes 2, min_conf 0.5, calib_mode exact) + `calibration.json` (204 وهم معتاد).
- **الرخصة:** تشترط عرض تنبيه الذكاء الاصطناعي لكل مستخدم ← موجود في آخر الصفحة (لا تشيله).
- **توقيت القارئ:** `data/reciters.json`، مولّد بأداتنا `server/align_reciter.py` (CTC forced alignment على نفس ملفات `audio/`)، ويفحص نفسه على وقفات الصوت؛ سورة ما تنجح ← `exact:false` (تظليل آية آية).
- **وضع العرض التجريبي:** `faseeh.space/?server=` لهالزيارة بس؛ التسجيل فيه ما يُحلَّل. (كان ينحفظ في المتصفح ويطلع أخطاء وهمية ← انصلح.)
- **وضع الفريق:** `faseeh.space/?team` ← يظهر سطر السيرفر ومربع i (CUDA / Hugging Face). `?team=0` يطفيه.
- **سطر "الخادم غير متاح"** يظهر فقط إذا السيرفر طافي **و** المستخدم ضغط تسجيل، ويختفي لحاله إذا رجع.

### الملفات المهمة
| المسار | ايش هو |
|---|---|
| `index.html` | الموقع كامل |
| `data/` | القرآن، الأحكام، المخارج، توقيت القارئ |
| `audio/` | تلاوة العفاسي لـ 78، 80، 103، 108، 112، 113، 114 |
| `server/faseeh_server.py` | السيرفر (نسخة منه في `server/hf_space/`) |
| `server/hf_space/` | ملفات Hugging Face (Dockerfile، requirements، config، calibration) |
| `server/local/` | تشغيل السيرفر على جهاز الفريق (Docker + ngrok + تحديث تلقائي) |
| `server/align_reciter.py`، `dump_align.py` | أداة توقيت كلمات القارئ |
| `server/evaluate.py`، `calibrate.py` | التقييم والمعايرة |
| `server/Faseeh_Server_Colab.ipynb` | الكولاب (تقييم، معايرة، توقيت) |
| `.github/workflows/sync-hf-space.yml` | مزامنة Hugging Face (يحتاج سر `HF_TOKEN`) |
| `docs/HANDOFF.md` | هذا الملف |

### جهاز الفريق (Windows 11، Ryzen 7 9800X3D، RTX 2080 8GB)
- المجلد: `E:\Faseeh_Local_Server` ← `start_faseeh.bat` / `stop_faseeh.bat` / `logs_faseeh.bat` / `remove_faseeh.bat`.
- **ما يشتغل لحاله أبداً** (طلب الفريق): لا عند تشغيل الجهاز ولا مع Docker.
- `settings.env` فيه توكن ngrok: **لا يُرفع أبداً**. (التوكن انكتب مرة في المحادثة؛ يُفضّل Reset.)
